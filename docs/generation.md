## 1. 从一块空板子决定怎么做

你的第一句是：「我有一个 esp32s3 的调试板，我想要对他做一些开发。」当时工作区是空的，你让 agent 上网找资料。丝印随后被确认：

- 板名：`ESP32S3 Large Model Board V1.1`
- 模组：`ESP32-S3-WROOM-1`（后来对照原理图定为 N16R8，16 MB Flash + 8 MB PSRAM）
- 厂家：幻尔科技，原理图 V1.0，日期 2025.10.30

你问过三条路：从 0 写，还是用现成环境；能不能把固件拷进 TF 卡来烧录；能不能自己写 bootloader、分区表、设备树。结论是走 ESP-IDF：第二级 bootloader 由 `idf.py` 编进 Flash，应用分区是单应用 1 MB。TF 卡拷贝不能代替 esptool 下载。自己的 bootloader 以后可以做，第一版先用 IDF 默认的。

你要的最小目标是：「我想做一个最小可运行的 hello world。」

调试口也是这时定的。板上有两路 USB：

| 口 | 芯片 | 当时的端口 | 能做什么 |
| --- | --- | --- | --- |
| USB-UART | CH340 | 曾经是 COM11 | 普通串口。下载不走这条 |
| 原生 USB | USB Serial/JTAG | 后来变成 COM8 | 下载和日志都走这里 |

你先插上 COM11，agent 试过连接。你说「好了，我断开了」，并要求把烧录命令留下来自己学。换到另一路 USB 之后端口变成 COM8，监视器里出现重复的 `Hello world!`，随后报 semaphore timeout。那是监视器占着口、对端复位造成的，退出监视再烧即可。从此约定：烧录用 `idf.py -p COM8 build flash`，不要把 `idf.py monitor` 留在后台。

### 按下 KEY3 就重启

你贴了按下 KEY3 后屏幕刷出开机画面、串口停在 `phy_init: phy_version 711` 的日志。你先拔电源，说问题消失了，可以进入 reconnect。然后要求软件在初始化时清掉这种状态，并同时报告：板子进了 reconnect、键盘也进了回连模式，两边就是连不上，只有重新 discover 才行。

软件侧做了两件事：启动时和第一次初始化蓝牙前，对 Wi-Fi/BT 电源域做一次关再开（`bluetooth_rf_reset`）；中断看门狗从默认 300 ms 放到 3000 ms，因为射频校准会长时间关中断。你确认过完整断电能恢复。软件复位写进了固件，但是不能把这次断电之前的射频卡死说成已经被软件证明修好。启动时会打印 `reset reason`。

### 短按回连，长按发现

你问过 BLE 的 inquiry 和 scan 是不是分别对应回连和配对。在 BLE 里没有经典蓝牙那种 inquiry；回连和发现都是扫描，差别在过滤和连谁。你定的手感是：

> 能不能让设备在按下 key3 后进入回连模式，长按 key3 进入发现模式。

- 短按 KEY3：屏幕写 `reconnect`。先按 NVS 里上次的地址直连，失败再扫描。回连扫描不要求广播里带 HID UUID。
- 长按约 1 秒：屏幕写 `discover`。只收 HID，然后一定弹出 KEY1–KEY3 / KEY4 选择。没有设备就写 `no input device`。
- 已经在扫描就写 `scanning`，不重入。

回连仍失败时，你把现象说成定向广播：

> 板子处于后台监听时，无法识别键盘带有加密标识/身份地址的定向广播。我想知道这个标识是被记录在蓝牙芯片中，还是需要额外的空间存储。

标识在 Flash 的 NVS 里，不在一块单独的“蓝牙存储芯片”上。绑定产生的 IRK 和身份地址在 `bt_config.conf`（`CONFIG_BT_BLE_SMP_BOND_NVS_FLASH`，最多 15 个）。控制器的 resolving list 是 RAM，每次开机从 NVS 装回去。定向广播如果 InitA 对不上当前本机地址，控制器会在协议栈交给应用之前丢掉，应用层看不到那一包。RPA 旋转周期是配置里的 900 秒。直连一个已经过期的可解析私有地址会失败；对端在 resolving list 里时，连身份地址有机会成功。

你问：「所以说这个蓝牙键盘只能每次都重新发现么？」不是。配对成功一次之后，短按 KEY3 走回连。长按发现用于第一次配对、键盘侧取消配对、或 NVS 被擦掉。固件要先有一次成功的 discover 连接，上次的地址才会写入 `bt_hid`。

### 回显和电池

你发现键盘回显没了：

> 键盘字符输入的回显应该正常显示，而不是在 enter 的时候一次性显示。敲击键盘正常回显，只是在 enter 的时候回车且发送给系统执行。

键盘行改成草稿行：每个可打印字符和退格都重写当前这一行（`lcd_text_set_draft`）。Enter 才收起草稿、把 `>一行内容` 提交给命令系统，再画新的草稿行。不能每个字符都 `append_line`，否则一字一行。

屏幕还会周期性出现 `battery 100%`。键盘仍在发电池通知，固件把这个事件空着，不再写到屏幕。

## 7. I2C、换行、trace、命令注册

你在 5 个 I2C 座上插了外设，要一条发现命令。`i2c` / `i2c scan` 扫 0x08–0x77。你问这和背光、按键是不是一条总线。是。`i2c_port_start` 只建一条总线，背光、按键、扫描和扩展座都用它。XL9555 一般在 0x20。

接着你要把 I2C 收成一个类，并加上读写调试：

> 添加一个 i2c 类，将 i2c 的相关功能转移进去，另外增加一些调试接口。

`I2c` 在 `i2c.cpp`。命令是：

- `i2c read <addr> <reg> [n]`，n 默认 1，最多 16
- `i2c write <addr> <reg> <bytes...>`

地址和字节可以用十进制或 `0x`。参数个数上限从 8 提到 16，否则写不了几个字节。第一次编译失败是 C++ 不能把 `int` 隐式转成 `gpio_num_t`，引脚号加上强制转换后烧录成功。Button 不再自己持有 I2C 设备句柄，改走 `i2c_reg_read` / `i2c_reg_write`。

长行是你对 `show_line` 提的：

> 如果字符数量超过 LCD_TEXT_COLS，分行显示。第二行要空格出提示符 `>` 的位置。

> 为了防止死循环，一次最多打印 5 行。超过了在第五行最末尾变成「信息不完整」。

字库只有 ASCII，屏幕上的截断标记用 `[...]`。续行第一个字符是空格，好跟 `>` 对齐。这段逻辑后来挪进 `trace` 的屏幕输出。

输出开关一开始是互斥的 `console`：

> 增加一个 console 输出的开关命令，控制输出到串口还是屏幕。添加一组 trace print 的 API 到一个新文件，替换当前工程代码中的所有打印。

`trace_print` / `trace_printf` 换掉了工程里的屏幕打印和这部分 `ESP_LOG`。默认走屏幕。

你随后改了语义，不再二选一：

> 把命令提示符改成 trace。选项分别控制对应的开关。`trace serial 1` 开启，`trace serial 0` 关闭。后面不带数字就输出当前状态。另外做一个 help。command 模块提供注册函数，负责 help。各自的命令在自己的模块里注册，内容包括关键字和简单描述。

现在是：

- `command_register(关键字, 说明, 函数)`，说明是一行 ASCII
- `help` 由命令模块自己登记
- `trace` 在 `trace.c` 登记，`color` / `splash` 在 `lcd_text.c`，`connect` 在 `bluetooth.c`，`i2c` 在 `i2c.cpp`
- 屏幕和串口默认分别是开、关
- KEY1|KEY4 只翻转串口这一路，屏幕保持原样

串口回车变成两个 `>`、光标掉到空行，是你在改 trace 之前报的：

```text
>>

>>

>>
```

你要求不要影响蓝牙键盘那一路。原因有两层。调试口收到换行后自己会回显 `\n>`，而 USB 驱动发送时已经把 LF 转成 CRLF。若 trace 再往串口打一行以 `>` 开头、并且自己又写了 `\r\n`，光标还停在上一个提示符后面，就会拼成 `>>`，再多出一个空行。主机若发送 CRLF，在“只把 CR 当换行、不吞掉后面的 LF”的模式下，一次回车还会变成两次。

改 trace 时一并处理了串口这一路：调试口提交的行只在屏幕开关打开时画到屏幕，不再从 trace 打回串口；串口 trace 只写 `\n`，让驱动去加 CR。蓝牙键盘提交时仍然打 `>一行`，因为键盘自己没有串口回显。

## 8. 串口被占用时的约定

烧录多次撞上 COM8 `PermissionError 13 拒绝访问`，通常是串口终端占着口。你要求做一个技能：agent 需要这个口、而口被占时，先问你三个选项——一次性确认、永久确认、还是拒绝——你点头之后才结束占用进程。这个技能在本机 Cursor 技能目录里，不属于固件。固件侧的约定不变：口被占就停下来问；口不存在就说明原生 USB 没插上，不去烧 CH340。

## 15. 超声波、点阵和系统字体

你要求做超声波驱动类。模块在扩展座那条 I2C 上，地址 `0x77`。`sonar` 无参数读距离，`sonar color` 和 `sonar breath` 各带 6 个字节设灯。

第一版距离算法被你否定。你给的 Python 是分开读 `DISDENCE_H` 和 `DISDENCE_L`，`distance = H*256 + L`，再 `float(distance)/10` 得到厘米。固件改成先读寄存器 1、再读寄存器 0，打印 `sonar u.u cm`。

你问两块 I2C 模块插在一起会怎样。五个扩展座是同一条总线，地址不同可以共存，地址相同会冲突。

接着你找到一块 LED 矩阵。网上常见的 16×8 TM1640（DIN/CLK）和 0.91 寸 SSD1306（`0x3C`）都对不上。你看到板背丝印是 `matrix-iic_v2.0`，并指出以前在 `D:\esp32\AiXiaoZhi_Hiwonder_Sensor` 里用过 `board.MatrixDisplayStatic`。驱动是 I2C `0x4C`：寄存器 `0x00` 亮度（`0x88`–`0x8F`），`0x01` 静态 16 字节（两块 8×8），`0x10` 滚动且没有方向。`matrix4c_send` 就是一帧 `[寄存器][数据...]`。

矩阵类和 `matrix` 命令按这个协议做：亮度、清屏、原始帧、滚动、命名图像（smile sad heart up box cross check fill）、分开显示时方向 1–4、两块屏拼一个 8×16 字符。静态更新先写 16 个 0，等 200 ms，再写画面。键盘回显不能在 HID 回调里做这 200 ms 空白，所以走一次直接写（`show_char_fast`）。`matrix key` 默认关。

字看起来只有约 5 列宽、又很长。font8x16 是 8 宽 × 16 高，墨水大约 5 列；拼到 16×8 点阵上时，上 8 行在左屏、下 8 行在右屏，所以一个高字符被左右拆开。8×8 的单屏横着放不下两个这种字。你要求字符离开左边缘，点阵侧每个字右移 1 像素，LCD 不移。

主键盘的 `>` `?` `.` 不显示，是因为 `hid_to_ascii` 当时只映射了字母、数字、空格和 `-`/`=`。标点补上之后，有一次烧录撞上 COM8 `PermissionError 13`，占用列表是空的，重试一次仍失败，没有杀进程。下一次 6 像素字体烧录成功，那次镜像里已经带上标点。

你要一套最宽 6 像素的 8×16 字，并要能切换。6 像素字由 5 像素字的中间一列重复得到，放在 `font8x16_w6.inc`。你随即指出切换不该放在 `matrix` 里，应放在新的 font 文件，因为它改的是整个系统（你写的是 “front”，按 font 做的）。`matrix font` 去掉。`font` / `font 5` / `font 6` 改全局字宽，默认 5。LCD 的 `draw_glyph` 和点阵的 `put_glyph` 都走 `font_glyph()`。切换成功后按屏幕上已有的行重画。点阵仍然只在自己这边右移 1 像素。

小键盘没反应是另一套 HID 码。主键盘数字是 `0x1E`–`0x27`，小键盘数字和 `/ * - + .` 是 `0x54`–`0x63`。映射补上后，Num Lock 打开才能打出数字。点阵回显仍要先 `matrix key 1`。

这一段里你还问过通信接口和板上还有哪些功能，以及触摸怎么用。只做了说明，没有新驱动。触摸在 GPIO4/5 的 `0x38`，当前固件找到 XL9555 后只留 GPIO38/48 那条总线。

最近一次烧到板子上的应用镜像是 `0xbe4b0` 字节，1 MB 分区大约还剩 26%。文档补完后一并推到 `origin/main`。
